The Full Dig — V-JEPA 2.1 + LoRA on MDS-UPDRS 3.4 Finger Tap

Mission: Surpass the v5 kinematic-features LightGBM baseline (QWK 0.7906, acc 0.6818) on fold 0 using only V-JEPA 2.1 features + LoRA + handcrop. No additional kinematic features.

Current state: Best V-JEPA ensemble QWK 0.7233 / acc 0.5758 — gap of −0.067 QWK, −0.106 acc. 1120+ classifiers trained across many SFT regimes; the feature ceiling under current constraints sits around QWK 0.72 (ensemble) / 0.68 (single).

1. Initial state & first attempt

Started with V-JEPA 2.1 ViT-L backbone + an existing temporal-stats-MLP probe pipeline that read mean-pooled features per tubelet, concatenated handcrop + nocrop features, and predicted a 5-class severity. Frozen-feature ensemble was around QWK 0.67–0.68.

First LoRA attempt (wide-frame, loose crop)

  • Trained LoRA r=8, α=16 on attn.qkv + attn.proj (1.18 M / 305 M params).
  • JEPA masked-prediction loss, 15 epochs, full-frame inputs (hand_crop=false).
  • Loss converged cleanly: 0.66 → 0.41.
  • Result: ensemble QWK 0.6519 — actually worse than the frozen baseline.
Conclusion: SSL on top of an already-strong general encoder doesn't automatically help. We needed to figure out why before iterating on hyperparameters.

2. Bugs found in the preprocessing pipeline

Pulled the 28 misclassified val clips. Almost every wide-angle shot showed the patient sitting in a chair with the hand occupying maybe 5–10% of the frame. We were "hand cropping" but the crop covered the torso.

Bug A — "Hand crop" was a torso crop

  • Default crop_scale=2.35 + crop_size=256 + bbox aggregated over all sampled frames → crop covered ~32% of frame on average, up to 68%.
  • Cosine similarity between cached handcrop and nocrop features: 0.958 — i.e. the "handcrop" wasn't doing anything.
  • Rewrote _mediapipe_hand_bbox in src/datasets/clip_dataset.py to use the median wrist position with a fixed-size box. Cropped to crop_size=128, crop_scale=1.5.
  • Cosine sim dropped to 0.889 mean, 0.7415 min — crops are now genuinely different from nocrop for most clips.

Bug B — Patient/camera handedness mismatch

  • MediaPipe labels hands from the camera's perspective; the manifest side column is from the patient's perspective. We were silently picking the wrong hand on every clip.
  • Fixed by inverting the side query before matching MediaPipe handedness.
Before/after frame samples

Before: bbox often covered both hands or just the resting hand. After: bbox tightly anchored on the tapping hand only.

Frame montages of the misclassified clips are saved at docs/results/lora_error_inspection/.

4. Error analysis on 1120 classifiers

Aggregated per-sample predictions across all 568 stored val_probs. For each val sample, computed the mode prediction across models and the fraction of models that agreed.

39% consistent-wrong → most models predict the same wrong answer with high agreement. This is a feature-level failure: the features don't encode what's needed to distinguish those samples. Better classifiers won't help.

The model can detect "normal" but cannot resolve adjacent severity grades (0↔1, 1↔2, 2↔3). 86% of errors are off-by-one; the high-severity tail is systematically under-predicted.

Verdict: The features lack the discriminating signal for fine-grained motor-severity grading. Better losses, bigger heads, or more ensembling cannot fix this.

7. Why we're stuck

Three lines of evidence all point at the same conclusion:

  1. 1120 trained classifiers, single-model QWK plateaus at 0.6764 — regardless of head architecture (stats-MLP, Transformer), loss (CE, CORN, MSE), or feature source (frozen / LoRA / LoRA+long / LoRA+temporal-mask).
  2. Reducing JEPA SFT loss makes the classifier worse, not better. The masked-prediction objective is misaligned with severity discrimination — better reconstruction does not imply better task features.
  3. Error pattern is class-adjacency confusion — exactly where fine-grained motion features (joint angles, tap rate, amplitude) would help and where the kinematic baseline wins by construction.
Under the current constraints (V-JEPA 2.1 features + LoRA + handcrop, no kinematic features, single-fold testing, 314 unique clips total), there is no realistic path past ~QWK 0.72. The kinematic baseline's advantage is fundamental: MediaPipe-derived joint kinematics directly encode the severity signal; V-JEPA's general visual features can't easily recover this from 248 finger-tap clips.
