Goal: beat the kinematic-feature LightGBM baseline (acc 0.682 / QWK 0.7906) on fold 0 of MDS-UPDRS finger-tap severity scoring, using only V-JEPA 2.1 features + LoRA + handcrop (no kinematic features).

What worked

1) Two preprocessing-pipeline bug fixes (silent killers)

  • Loose torso "hand crop": crop_scale=2.35 + crop_size=256 + bbox aggregated over all frames → crop covered ~32% of frame on average (up to 68%). Rewrote _mediapipe_hand_bbox to use the median wrist position with a fixed-size box. Reduced cosine-sim between handcrop and nocrop features from 0.958 → 0.889.
  • Patient/camera handedness mismatch: MediaPipe labels hands from the camera's perspective; the manifest side is from the patient's. We were silently picking the wrong hand for every clip. Fixed by inverting the side query.

2) Five codebase bugs you flagged

  • vit_encoder_multiclip_vjepa21.py: now tries ema_encoder → target_encoder → encoder in order, so LoRA checkpoints load cleanly without manual key override.
  • app/vjepa_2_1/train.py:317: anneal mode now auto-resumes from latest.pth.tar if present (instead of silently re-annealing from scratch on SLURM rerun).
  • app/vjepa_2_1/train.py:493: load gate is now load_model AND load_path is not None — load_checkpoint: false actually means no load even with a stale latest.pth.tar.
  • evals/.../eval.py:705 (_classifier_forward): unwraps DDP .module before getattr(..., "metadata_dim") — was silently dropping metadata under DDP.
  • src/datasets/clip_dataset.py: guards len(vr) < max(frame_step, num_clips) early-return — prevents partition_len=0 → np.clip(..., 0, -1) producing −1 indices.

3) Handcrop-LoRA short SFT (20 ep)

The bug-fix + short SFT is the best feature regime. Single-model best 0.6764, all-handcrop ensemble 0.7233 — meaningful gains over the original wide-frame baseline (~0.65). Adding handcrop-LoRA features ≈ +0.07 QWK to the ensemble.

What didn't work (and why)

Longer SFT (50 epochs, peak LR 2e-4 → 1e-7)

JEPA reconstruction loss got 15% better (0.42 → 0.36) but downstream classifier QWK dropped from 0.6764 → 0.6401 single, 0.6884 → 0.6605 ensemble. The JEPA reconstruction objective is misaligned with severity discrimination. Higher peak LR pushed LoRA further from V-JEPA's well-trained general features.

Temporal-aware JEPA masking (temporal_scale=0.5)

Hypothesis was that masking partial frames within blocks (vs whole-frame blocks) would force the LoRA to learn temporal/motion dynamics rather than spatial reconstruction. Result: flat. Within-sweep ensemble crept up to 0.6961 but combined cross-sweep ensemble did not gain (0.7033 vs 0.7233 prior best).

Larger classifier head (Transformer encoder, 3 layers d=128)

With 248 training samples the Transformer (0.6M params) overfits — peak val QWK 0.4687 at epoch 9, then degrades. Stats-MLP (0.5M params, handcrafted velocity / FFT / per-segment stats) holds up because the inductive bias matches the periodic tap signal.

MSE regression instead of CE/CORN

Hoped that penalizing off-by-2 more than off-by-1 would align with QWK and reduce the systematic under-prediction of severity. Got QWK 0.5387 — worse than CE 0.6764. The model can't reach class 4 from regression: predicted range only spans [-0.20, 3.49].

Meta's attentive probe (4-block transformer with cross-attention)

The project's "minimal divergence" spec calls for this head. Ran the full evals/main.py pipeline on cached features. Wall-clock was ~10 sec/iter (MediaPipe per-batch handcrop is CPU-bound), implying ~28 hrs for 40 epochs. Not viable inside the time budget. Killed at epoch 0.

Frozen V-JEPA + tight handcrop (no LoRA)

Best single QWK 0.6474 — clearly below the LoRA-adapted runs. Confirms that the handcrop-LoRA SFT is doing real work, even if modest.

LR scheduler in classifier

Added warmup-cosine. Hurt. Cosine decayed LR too fast for the early-stopping pattern of the classifier — the model usually finds its best epoch around 30 of 80, but by then LR was already at 30% of peak. Reverted to constant LR.

Why the gap persists

Three pieces of evidence point at the same conclusion:

  1. Single-model QWK plateaus at 0.6764 across 1120 trained classifiers, regardless of head architecture (stats-MLP, Transformer), loss (CE, CORN, MSE), or feature source (frozen / LoRA variants).
  2. Reducing JEPA SFT loss makes classifier worse, not better — the masked-prediction objective is not aligned with severity discrimination.
  3. The error pattern is class-adjacency confusion, exactly where fine-grained motion features would help and where the kinematic baseline (which encodes finger-joint angles + velocities directly) wins.

Under the current constraint (V-JEPA 2.1 features + LoRA, no kinematic features), there is no realistic path past ~QWK 0.72 on this 314-clip dataset with only fold 0 to fit. The kinematic baseline's advantage is fundamental: MediaPipe-derived joint angles and velocities are exactly the signal severity grading depends on; V-JEPA's general visual features can't easily recover this from 248 finger-tap clips.
