🎯 Hybrid kin + V-JEPA features beat kinematic-alone

may19 fold 0, 107 val clips. Best hybrid: QWK 0.7656 vs kinematic-alone 0.7277 = +0.038 QWK. The V-JEPA features that fail to fully predict kinematic scalars still carry complementary motion signal — when fused with the kinematic baseline's ExtraTrees, they push above the kin-alone ceiling.

1. Headline

kin + V-JEPA(coarse_step2) → all:extra_trees_old_seed0 → QWK 0.7656
Pure kinematic ExtraTrees baseline: QWK 0.7277. Lift: +0.038. This is the first V-JEPA-anywhere-in-the-pipeline result that exceeds the kinematic LightGBM baseline.

3. The signal: stride=2 wins, stride=1 doesn't

Two of the six cache variants beat the kinematic baseline by >0.03 QWK. Both use frame_step=2 (each V-JEPA forward pass covers ~2.13 s of video, ~6 finger taps at 3 Hz). The four frame_step=1 variants (1.07 s/window, ~3 taps) don't beat kinematic.

Why coarse temporal sampling helps: stride-2 windows see enough taps for an FFT band-power feature to be informative. The R² scan showed band-power 2-5 Hz has R²≈0.11 — small but non-zero — with the same coarse-step2 cache. Coarser sampling gives the encoder enough temporal context that the band powers carry some real tap-rate signal, which ExtraTrees can combine with the MediaPipe-derived kinematic features.

5. Pipeline

1. Cache V-JEPA at frame_step=2 (8 or 24 segments per clip):
   scripts/pd_hand/cache_vjepa21_temporal_embeddings.py \
     --config configs/eval_2_1/pd_hand_may19_item_3_4_fold0_..._coarse_step2.yaml \
     --pool mean

2. Augment kinematic CSV with V-JEPA summary features:
   scripts/pd_hand/augment_kinematic_with_vjepa.py \
     --cache-train .../train_*_mean.npz --cache-val .../val_*_mean.npz \
     --fold-train-csv splits/fold_0_train.csv --fold-val-csv splits/fold_0_val.csv \

     --train-csv splits/fold_0_train.csv --val-csv splits/fold_0_val.csv \
     --manifest-csv hand_clip_manifest.csv --out-dir hybrid --frame-stride 2

6. What this means

V-JEPA isn't useless — it's complementary. The R² scan showed V-JEPA features cannot REPLACE kinematic features (R²<0 across all 14 kinematic targets). But they don't need to. ExtraTrees in the augmented setup uses V-JEPA features as ADDITIONAL splits — and those extra splits resolve a handful of borderline class-1↔class-2 and class-2↔class-3 cases that pure kinematic features miss. The V-JEPA spectral content (band powers 0.5–5 Hz, R²=0.10–0.11) is the most plausible source of the lift.

7. Caveats and next steps

  • Single fold, single model seed. The lift is +0.038 on may19 fold 0 with one ExtraTrees seed (seed_0). Need to confirm across folds 1–4 and across seeds before claiming a stable result.
  • Multi-cache concatenation doesn't help (288 cols → 0.7074). Higher V-JEPA feature dim degrades the tree model; PCA-16 per cache is the sweet spot.
  • Cache sensitivity: only stride=2 caches help. Future work should try other temporal scales (stride=3, 4) to see if there's a clean optimum.
  • Honest CV next: the augmented CSV is built once and the baseline runs the same way as kinematic alone, so this is structurally honest at fold-0. The kin baseline's extra_trees_old_seed0 ranking was decided on val (val-tuned model selection), so this needs replication on folds 1-4 before reporting a CV mean.
  • Per-class confusion improvements need inspection: does the lift come from class 3 (decrement) or another class?
