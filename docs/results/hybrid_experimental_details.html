Hybrid kin + V-JEPA experimental details

Full mechanics behind the clean hybrid result (may19 fold 0): kin + dx alone gets QWK 0.559 ± 0.023; adding 5 V-JEPA OOF combiner probabilities lifts it to 0.589 ± 0.014, +0.030 mean, 9/10 seeds win, Wilcoxon p=0.003. This page documents every choice in the pipeline so the result is reproducible.

The V-JEPA features we stack come from a frozen pass through a LoRA-fine-tuned V-JEPA 2.1 ViT-L encoder. Two stages:

The merge step (scripts/pd_hand/merge_lora_from_base.py) adds the LoRA deltas to the base weights for all 24 transformer blocks (48 LoRA pairs in qkv + proj). The result is a 1.16 GB checkpoint that loads with the standard V-JEPA encoder code, no LoRA adapter required at inference.

3. The V-JEPA combiner

The combiner is the small transformer that turns the cached [T, 1024] sequence into 5 CORN class probabilities. It is trained per inner fold (and then once more on full train) to produce the OOF stacking features.

HyperparameterValue
ArchitectureTemporalCornCombiner (in scripts/pd_hand/train_corn_combiner.py)
Input projectionLayerNorm → Linear(1024 → 128) → GELU
Positional encoding2D learned: seg_idx ∈ [0, 48) embedding + within_seg_idx ∈ [0, 16) embedding, summed
Transformer body2 layers, 4 heads, d_model=128, FFN mult 4, dropout 0.3, pre-norm
ReadoutLearnable CLS token (with its own positional add) at sequence head; transformer output[CLS] → LayerNorm → Linear(128 → 4)
OutputCORN ordinal logits (K−1 = 4 binary levels). Probabilities derived via cumulative product → 5-class distribution.
LossCORN conditional BCE, pos_weight clipped to [0.25, 4.0] per level (avoids the class-4-sparsity blowup)
OptimizerAdamW, lr 3e-4, weight_decay 0.05
LR scheduleLinear warmup 8 epochs → cosine to 3e-5 over 100 epochs
Train epochs / patience150 / 80
Batch size16
Trainable params~0.55 M

The combiner sees the variable-length cache via a (x, mask) tuple per scale and uses the mask as the transformer's key_padding_mask so padded positions don't contribute.

4. Subject-OOF inner cross-validation

The combiner trained on the full fold-0 train will overfit (train CORN loss → near 0 within ~30 epochs). Using its predictions on train as features would leak labels into the stacking step. We use subject-grouped stratified K-fold instead:

ChoiceDetail
Splittersklearn.model_selection.StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=0)
Groupssubject_id from the fold-0 train CSV, lifted into cache row order via sample_index
Stratification targetPer-clip label (0–4) — within each inner fold the label distribution is balanced
Inner-fold sizes~324 inner-train / ~80 inner-val per fold (subject-grouped, so subject counts: ~156/39)
Per-fold combiner OOF QWK (sanity)0.563, 0.585, 0.624, 0.629, 0.587 — mean ≈ 0.60
Final val combiner QWK0.34 (single best epoch, full-train) — note this is the combiner's own argmax on val; the stacking model uses the soft probabilities not the argmax

The per-inner-fold OOF QWK of ~0.60 is higher than the full-train val QWK of 0.34 because the full-train run hits early stopping on a noisy val curve. For the stacking step we use the soft probabilities (5 numbers per clip), not the argmax decision, so the noisy argmax doesn't matter as long as the probability vector is informative.

5. The kinematic baseline feature set

The reference baseline for "is V-JEPA helping?" is the kinematic features alone. We considered three definitions:

VariantColsWhat's includedQWK mean ± std (10 seeds)
kin_only 99 bbox-area / flip-bbox-area statistics from MediaPipe: mean/std/percentiles/peak counts/FFT bands/velocity/acceleration etc. No diagnosis, no item 3.5 score. 0.397 ± 0.045
kin + dx 106 kin_only + 7 non-leak meta features: dx_HC/NDC/PD/PPD, side_right, duration_s_manifest, start_s_manifest. Diagnosis is provided clinically (not a UPDRS item label). 0.559 ± 0.023
old_118 (the published "baseline") 118 kin + dx + 12 columns derived from rater UPDRS item 3.5 (hand movements): item35_same, item35_other, plus their 5-way one-hot encodings. 0.725 ± 0.010
Why we use kin + dx as the clean baseline: item 3.5 (hand movements) and item 3.4 (finger tapping) are correlated within a patient (~0.7 Spearman on this cohort). The rater is the same person, scored at the same visit. Using item 3.5 to predict item 3.4 is highly informative but borderline-leaky: it conflates "what the patient looks like on video" with "what the rater scored on a related task." For an honest "can video predict severity?" claim, we exclude item 3.5. Diagnosis (dx_*) is kept because it's an inclusion criterion known before testing — not derived from this clip's labeling.

The 5 V-JEPA probability columns are appended to the kinematic feature CSV before training a single tree ensemble:

Missing valuesSimpleImputer(strategy="median") applied as the first pipeline step

This matches the existing kinematic baseline's extra_trees_old_seed0 configuration (n_estimators bumped from 80 → 1000 for variance reduction; that change applies equally to both compared models).

7. Multi-seed evaluation protocol

ExtraTrees is non-deterministic. To distinguish "V-JEPA helps" from "this seed happened to be lucky" we ran the full comparison 10 times with different random_state values. The same seed is used for kin+dx and for kin+dx+V-JEPA on each iteration, so the only difference between paired runs is the presence of the 5 V-JEPA columns.

Seeds used
0, 1, 2, 3, 17, 42, 98, 233, 777, 1234

The V-JEPA pipeline (LoRA-FT, cache extraction, combiner training across 5 inner folds, full-train combiner for val) is run once. The same train_probs[404, 5] and val_probs[107, 5] are used across all 10 ExtraTrees seeds.

8. Statistical test

For each seed we record paired QWK values (kin baseline and hybrid). The Wilcoxon signed-rank test on the 10 paired differences tests whether the hybrid's per-seed QWK is systematically greater than the baseline's:

scipy.stats.wilcoxon(hyb_qwk, base_qwk, alternative="greater")
  → statistic = 54.0, p_one_sided = 0.0029

9/10 paired differences are positive. The single negative (seed 98) has Δ = −0.008, well below the typical magnitude of the positive differences.

Headline: on the clean baseline (kin + dx, no UPDRS item 3.5 leak), adding 5 V-JEPA OOF combiner probabilities lifts QWK by +0.030 mean (9/10 seeds, Wilcoxon p = 0.003). The lift comes with reduced seed variance (0.023 → 0.014), so V-JEPA stacking is making the prediction more stable, not less.
Negative result on the leaky baseline: when item 3.5 is in the feature set (the published 0.725 baseline), V-JEPA OOF probs actually HURT (0.725 → 0.695). Two explanations:
  • Item 3.5 score is a much stronger predictor than 5 V-JEPA probs, so adding the latter just dilutes the trees' splits.
  • The V-JEPA combiner was trained without access to item 3.5, so it has learned to predict item 3.4 from video; that signal partially conflicts with the item 3.5 signal in disagreement zones, and ExtraTrees can't reconcile them.
This is why we report the clean comparison — it's the right question (video-only severity prediction) and the answer is positive there.

10. Caveats and limitations

  • Single outer fold. All numbers are on may19 fold 0 (107 val clips). The +0.030 mean lift is well above seed noise but a single-fold result. To be journal-grade we should repeat across folds 1-4 and report a 5-fold CV mean.
  • One combiner config. The V-JEPA combiner used here is d_model=128, 2 layers, 4 heads. Earlier sweeps found similar configs were near-optimal for this dataset size, but we didn't sweep again inside the OOF pipeline.
  • One V-JEPA encoder. The LoRA-FT encoder used was the rank-16 attn-only run that completed cleanly. Other LoRA-FT runs (rank 32 + MLP, rank 8) collapsed at fit time — those features were not tested for OOF stacking.
  • Subject grouping is approximate. Some patients have multiple visits; we group by subject_id which keeps all visits together — that's conservative.
  • n=404 train, n=107 val is small. The Wilcoxon p=0.003 is significant under the multi-seed paired design but the absolute lift (+0.030) is comparable to the seed noise (≈ 0.020). Real-world deployment claims should wait for 5-fold CV confirmation.
  • Class 4 has 0 samples in val and 1 in train. All QWK numbers therefore reflect performance on classes 0-3 only. The lift might look different on a dataset with more class-4 severity examples.

11. Reproducing the pipeline end-to-end

# 0. Build manifest + folds (one-time)
python scripts/prepare_minimal_hand_vjepa2.py \
    --segments-root /gpfs/.../segments_meeting_tasks_720p30_may19 \
    --out-dir outputs/foundation_model_minimal_hand_tasks_may19

# 1. Kinematic baseline (provides train/val_features_stride2.csv + the 0.725 result)
sbatch scripts/pd_hand/run_kinematic_baseline_may19_item_3_4_fold0.sbatch

# 2. Supervised LoRA-FT of V-JEPA 2.1 ViT-L (rank 16, attn-only, 30 epochs)
sbatch scripts/pd_hand/run_supervised_lora_ft_aggressive_may19_item_3_4_fold0.sbatch

# 3. Merge LoRA delta into base
sbatch scripts/pd_hand/run_merge_lora_aggressive_may19.sbatch  # depends on step 2

# 4. Adaptive cache (K_i = ceil(duration_s), max 48)
sbatch scripts/pd_hand/run_cache_loraft_aggressive_adaptive_may19.sbatch  # depends on step 3

# 5. Subject-OOF inner CV combiner predictions
sbatch scripts/pd_hand/run_oof_loraft_combiner.sbatch  # writes oof_loraft.npz

# 6. Augment kinematic CSVs with the 5 OOF prob columns
python scripts/pd_hand/augment_with_oof_probs.py \
    --oof-npz hybrid/item_3_4/fold_0/oof_loraft.npz \
    --fold-train-csv splits/item_3_4/fold_0_train.csv \
    --fold-val-csv   splits/item_3_4/fold_0_val.csv \
    --kin-train-csv  kinematic_baselines/item_3_4/fold_0/train_features_stride2.csv \
    --kin-val-csv    kinematic_baselines/item_3_4/fold_0/val_features_stride2.csv \
    --out-train-csv  hybrid/item_3_4/fold_0/oof_stack/train_features_stride2.csv \
    --out-val-csv    hybrid/item_3_4/fold_0/oof_stack/val_features_stride2.csv \
    --prefix vjepaOOFprob

# 7. 10-seed ExtraTrees comparison
python scripts/pd_hand/hybrid_multiseed.py \
    --train-csv  hybrid/item_3_4/fold_0/oof_stack/train_features_stride2.csv \
    --val-csv    hybrid/item_3_4/fold_0/oof_stack/val_features_stride2.csv \
    --vjepa-prefix vjepaOOFprob \
    --seeds 0,1,2,3,17,42,98,233,777,1234 \
    --n-estimators 1000 \
    --old-118-cols hybrid/item_3_4/fold_0/old_118.json \
    --out-json hybrid/item_3_4/fold_0/oof_stack/multiseed_oof_probs.json
