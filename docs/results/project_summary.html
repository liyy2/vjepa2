Yunyang Li · Scherzer lab, Yale · 2026-05-24 · item 3.4 finger tapping, may19 dataset.

Bottom line: Under a strictly leak-free protocol, V-JEPA 2.1 features add no measurable signal over a kinematic + demographic baseline for predicting MDS-UPDRS item 3.4 severity. 1. Problem & scope

One model per item, ordinal MDS-UPDRS score (0–4) for a single hand-task clip. v0 spec lives in foundation_model_minimal_hand_tasks.md; the guiding principle was minimal divergence from Meta's V-JEPA 2.1 reference — change only the dataset class, the head (CORN ordinal over 5 levels), and the loss. Backbone, attentive probe, optimizer, multi-clip aggregation: stay at Meta's defaults.

This summary covers item 3.4 finger tapping end-to-end. Item 3.5 (hand movements) has not yet been run through the leak-free protocol.

2. What we built (timeline)

phase 1
Pipeline scaffolding
May19 finger-tap manifest, subject-level 5-fold splits, kinematic LightGBM baseline (v5 features), fixed-K LoRA CORN attentive probe on fold 0.
phase 2
Better V-JEPA temporal features
Cached temporal-stats stacker; spatial-pool/temporal-keep extractor; learned cross-window combiner (replaces logit-mean); multi-scale tubelet features (coarse/fine).
phase 3
Iterate until V-JEPA ≈ kinematic
Aggressive adaptive Ki sweeps, bigger epoch budget, LoRA depth/rank sweeps, multi-scale combiners, MIL variants, warmstart. Plateaued well below kinematic.
phase 4
R² scan
Asked the prior question directly: can any V-JEPA cache/reducer/model linearly predict the kinematic features? Across 54 configs, mean R² = −0.117. The V-JEPA representation does not contain the kinematic signal in any easily-recoverable form.
phase 5
Hybrid (kin + V-JEPA)
Stack OOF V-JEPA probs onto the kinematic feature set with ExtraTrees. First pass: +0.030 QWK on fold 0. Looked publishable.
phase 6
Leakage audit
Two leaks identified: (i) backbone best.pt was selected by val QWK; (ii) the inner V-JEPA combiner returned the best-val-QWK epoch. Both implicitly tune on the same val set the stacker is evaluated on.
phase 7
Leak-free 5-fold replication
Use latest.pt for LoRA, add --no-val-tuning to the combiner, replicate across all 5 folds × 10 seeds. Pooled across 50 fold×seed pairs: Δ QWK = −0.004, p = 0.71. Null.

The leak-free protocol additionally uses latest.pt instead of best.pt for the LoRA backbone, and a --no-val-tuning flag in the combiner — both are evaluation-protocol changes, not architecture changes.

5. Why V-JEPA didn't help here

  • Small N. ~1,200 clips → ~240 per held-out fold. Cross-fold std (±0.055) is >10× the hybrid Δ.
  • The signal V-JEPA encodes ≠ the signal that matters. R² scan shows V-JEPA features cannot linearly recover kinematic measures (mean R² = −0.117 across 54 configs). The 1–5 Hz finger-tapping rhythm and amplitude decrement that drive UPDRS scoring are not isolated in the V-JEPA latent.
  • Kinematic features are already strong. Hand-crafted v5 features capture exactly what the rater is grading. Adding V-JEPA probs through ExtraTrees has nothing orthogonal to add.
  • Earlier "wins" were val-tuning leaks. Once both implicit val-selection paths are closed, the lift vanishes.

7. Open questions / next directions

For the paper: the null result is a result — V-JEPA 2.1 features do not improve a clinical kinematic baseline for finger-tapping severity at this dataset scale, despite a careful adaptation. That claim is publishable on its own if framed as a negative result + leakage methodology contribution.
  • Item 3.5 (hand movements) — replicate the same leak-free protocol to confirm the null isn't item-specific. Highest-value next experiment; pipeline already exists.
  • V-JEPA → kinematic distillation — auxiliary loss during LoRA-FT that forces the probe to predict scalar kinematic measures. Possible way to anchor the V-JEPA latent to the relevant axes.
  • Hand-specific video models — a model pre-trained on egocentric / manipulation video may carry more of the right signal than V-JEPA's general action prior.
  • Bigger N — the across-fold std swamps any small effect; only more clips fix this.
Methodological takeaway: in any stacked / cached features pipeline with subject-level CV, audit two things every time — (i) where backbone checkpoints are selected, (ii) where intermediate predictors return their epoch. Both are subtle val-tuning paths that compound into a fake lift.
