What happened — chronological summary

1) First LoRA attempt — wide-frame, loose-crop (no gain)

  • Trained LoRA (rank=8, target attn.qkv + attn.proj, 1.18M trainable / 305M total) with JEPA masked-prediction loss for 15 epochs on the 248 PD finger-tap clips.
  • Inputs: whole-frame wide-angle clips (hand_crop: false).
  • Loss: 0.66 → 0.41 (clear convergence).
  • Cache + velocity-grid sweep with handcrop+nocrop concat features.
  • Result: ensemble QWK 0.6519 — actually worse than the frozen baseline (~0.681).
  • Conclusion: LoRA self-supervised adaptation didn't help when trained on the same wide-frame view that the cache used.

2) Error analysis on misclassifications — two real bugs found

Pulled the 28 misclassified val clips, looked at frame montages:

Off-by-2: y=2 → p=0. Patient is a wide-angle full-body shot; hand is tiny in the frame.
Off-by-2: y=2 → p=0. Same problem — hand is a tiny fraction of the frame.

The pattern was consistent: the hand is too small in the frame for spatial mean pooling to preserve fine-grained finger motion.

Bug A: "Hand crop" was actually a "torso crop"

The cosine similarity between cached handcrop features and nocrop features was 0.9578 on average — meaning the hand crop was barely doing anything. Diagnosed and found two issues in src/datasets/clip_dataset.py:

  • Loose crop scale: crop_scale=2.35 + crop_size=256 + bbox aggregated over ALL sampled frames → "hand crop" covered ~32% of frame on average, up to 68%. Effectively a torso shot.
  • Bbox aggregates motion: _mediapipe_hand_bbox took the bounding box over ALL sampled frames' wrist positions → bbox expanded with motion. Rewrote to use the median wrist position with a fixed-size box.

Bug B: Patient-vs-camera handedness mismatch

For Y00137 patient-right tap (visible in upper-left of camera frame), MediaPipe was selecting the patient-LEFT hand (resting on lap, lower-right):

BEFORE fix: patient-right tap (upper left). Old bbox = wrong hand + huge area.
AFTER side-swap fix: bbox now anchored on the patient's right (tapping) hand.

Root cause: MediaPipe's handedness label is from the camera's perspective; the manifest's side is from the patient's perspective. These are mirrored. Fixed by inverting the side query before matching.

3) Retrained LoRA with tight-handcrop inputs + bug fixes

  • 20-epoch LoRA training with hand_crop=true, crop_size=128, crop_scale=1.5.
  • Loss: 0.555 → 0.420 (similar trajectory to wide-frame).
  • Cache jobs reran with the same crop params → handcrop vs nocrop cosine similarity now 0.8893 mean, 0.7415 min (was 0.9578). Crops now genuinely different for many clips.

4) Sweep + cross-ensemble on handcrop-LoRA features

Two grids run × 4 shards × ~50 configs each:

  • velocity grid (48 × 4 = 192 configs): single best QWK 0.6304, ensemble (K=9) QWK 0.7033.
  • mega_seeds grid (45 × 4 = 180 configs, 30 seeds × 6 recipes): single best QWK 0.6764 (with fft_mode=global, use_velocity=False — different recipe from velocity).
  • Best cross-ensemble across all handcrop sweeps (incl. wide-frame LoRA): greedy K=5 → QWK 0.7233, acc 0.5758.

5) Currently running — frozen V-JEPA with tight handcrop

Caching frozen V-JEPA features with the same tight handcrop, then running velocity + mega_seeds sweeps on those. Goal: add ensemble diversity from a different encoder view (frozen vs LoRA-adapted). If both encoders produce complementary signals, the combined greedy ensemble should improve.

Key takeaways

  1. Two real bugs in the preprocessing pipeline (loose torso "hand crop", and patient/camera handedness swap) — both fixed and committed conceptually. These were silent but materially hurt performance.
  2. LoRA self-supervised adaptation alone is not enough. Training on 248 clips × 20 epochs is too little signal vs. the internet-scale frozen V-JEPA, especially with the masked-prediction objective being only loosely related to severity discrimination.
  3. Hand-crop + LoRA together (with the bug fixes) does help ensemble QWK climb from 0.65 → 0.72, but the gap to 0.79 remains. Single-best QWK is roughly flat across configurations.
  4. The data-limited regime is the real bottleneck. 248 train / 66 val, with only 5 high-severity examples in val — every model under-predicts the tail. This is hard to fix without (a) more data, (b) richer per-clip TTA, or (c) merging in modalities the spec explicitly rules out.
