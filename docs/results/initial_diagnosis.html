Why the attentive-probing pipeline is not learning, and what to do about it.

TL;DR

The probe head does extract ordinal signal from V-JEPA features — Spearman runs 0.30 → 0.51. But at decision time it collapses to majority class: val_acc ≈ 33 %, QWK ≈ 0. Meanwhile a hand-crafted LightGBM/ExtraTrees baseline on the same fold gets acc 68 %, QWK 0.79. Signal is in the data; this pipeline isn't recovering it.

The root cause is a stack: a 49 M-parameter probe on 248 training samples, a multi-clip aggregation that silently departed from Meta's recipe, and an effective global batch size of 3.

4. Root causes, ranked

#1
49 M-parameter probe trained on 248 samples
critical

The 4-block AttentiveClassifier / CORNAttentiveClassifier has 49.34 M trainable params. Meta tuned it on SSv2 (~220 k clips). Your fold-0 train has 248 clips → ~200 k params per training sample, ~900× Meta's ratio.

The stats head (1.58 M params) gets the best Spearman you've recorded (0.51) — exactly what an over-parameterization story predicts.

files: src/heads/corn_head.py · src/models/attentive_pooler.py

#2
Multi-clip aggregation drifted from Meta's spec
critical

Spec (§3 of foundation_model_minimal_hand_tasks.md) and Meta both say: K independent encoder passes → K probe outputs → average logits.

Current pipeline instead token-concatenates all 12 segments along the temporal axis into one ~110 k-token sequence, runs the probe once, then averages softmax over num_views_per_segment = 1 (i.e. no averaging at all).

Consequences: the probe self-attends over 110 k tokens; temporal structure has to be discovered from a sinusoidal pos-embed stamped on the fly; the regularizing piece of Meta's recipe (logit averaging across K clips) never fires.

files: evals/video_classification_frozen/modelcustom/vit_encoder_multiclip_vjepa21.py:103–149 · evals/video_classification_frozen/eval.py:571

#3
Effective global batch size is 3
high

Meta SSv2: batch=4 × 8 nodes × 8 tasks = 256. All PD configs: batch=1, nodes=1, tasks_per_node=3 → 3. The LR/WD sweep was calibrated for batch 256; running lr=3e-3, wd=0.4 at batch 3 is on the edge of divergence and explains the noisy per-epoch jumps in fold_0_ddp3.

file: configs/eval_2_1/pd_hand_item_3_4_*.yaml

#4
Class 4 essentially absent; class 3 rare
high

Item 3.4 fold-0 train: 0=77, 1=86, 2=66, 3=19, 4=0. CORN's threshold-3 logit never sees a positive in training; balanced softmax gives class-4 weight 0. Item 3.5 has zero class-4 samples anywhere.

You're asking a 5-level CORN to model what is effectively a 4-class label space.

file: splits/item_3_4/fold_0_train.csv

#5
CORN loss is unmasked
medium

corn_loss applies BCE to all K-1 thresholds for every sample. The Cao et al. 2020 CORN the spec calls out is conditional: threshold j only gets gradient from samples with y > t_{j-1}.

Without the mask, you've built CORAL without the shared-weight constraint — the rank-monotonicity guarantee is gone, and the easier high-threshold tasks dilute gradient on the hard ones.

file: src/losses/corn_loss.py:35

#6
SSv2-tuned augmentation is destructive at this data scale
medium

make_dataloader defaults: random_resize_scale=(0.08, 1.0), auto_augment=true, reprob=0.25. A 0.08-scale crop on a 384² frame is 109² pixels — almost certainly drops the hand entirely.

Your noaug_nocrop run did not actually move the needle (30 % vs 36 %) so this is not the dominant cause, but combined with #1 and #2 it pushes things further.

file: evals/video_classification_frozen/eval.py:997–1015

#7
Head selection bias over 12 LR/WD heads on 66 val samples
minor

_best_metric_index picks the top val metric across 12 classifiers. With per-head val noise ≈ 6 pp on 66 samples, "best of 12" biases the headline number upward by ~1–2 points. Small but worth knowing when comparing variants.

file: evals/video_classification_frozen/eval.py:816–821

5. Recommendations, in priority order

1
Bound the feature ceiling first. Run frozen backbone → global average pool → single linear → CE. If that can't clear majority baseline + Spearman ~0.4, the issue is the V-JEPA features themselves and no probe tweak will save you. one new config; ~30 minutes to launch
2
Restore Meta's logit-averaging recipe. Either (a) drop to num_segments=2, num_views_per_segment=3 like SSv2 and remove the temporal token-concat from ClipAggregation, or (b) change multiviews_postprocess to return one tensor per (clip × view) so the probe runs K times and eval.py:571 actually averages K softmaxes. touches the wrapper that drifted in the first place
3
Cap the LR sweep. At global batch 3, the lr ∈ {1e-3, 3e-3} rows are not useful — try lr ∈ {3e-4, 1e-4} × wd ∈ {0.01, 0.1} only. Fewer heads, cleaner pick. config-only change
4
Make the CORN loss conditional per Cao et al. 2020 (mask sample i out of threshold j's BCE when label_i ≤ j). Three lines in src/losses/corn_loss.py. restores the rank-monotonicity guarantee
5
Collapse the label space to 0–3. Merge class 4 into class 3 (or drop the handful of class-4 clips). Document the choice; a 5-level CORN over zero class-4 training samples is misleading. data manifest change in the sister project
6
Until logit-averaging is back, set random_clip_sampling=False for train. With token-concat and global batch 3, per-step gradient noise is dominated by random clip offsets per epoch. flag in the dataset_kwargs / clip dataset

The minimal-divergence principle in CLAUDE.local.md still holds. Item 2 is restoring Meta's recipe, not deviating from it — the current ClipAggregation is itself a silent deviation.
