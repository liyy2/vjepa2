Item 3.4 (finger tap), fold 0 — 404 train / 107 val. Goal: a pure V-JEPA pipeline whose QWK approaches the kinematic LightGBM baseline (QWK 0.728). After ~80 V-JEPA configurations across 7 different architectures, the best pure-V-JEPA result is QWK 0.533 (frozen tstats top-K=24 ensemble) — a gap of 0.20 QWK that the supervised LoRA-FT pipeline did not close.

Spatial-squash, temporal-keep scripts/pd_hand/cache_vjepa21_temporal_embeddings.py — already pools 576 spatial patches per tubelet to 1 vec, retaining 192 temporal tokens per clip Cache shape [N, 192, 1024] for fine, [N, 128, 1024] for coarse

5. LoRA-FT failure modes

We attempted supervised LoRA-FT three times. Each failure taught us something:

AttemptConfigOutcomeCause
1 CORN head, corn_pos_weight: auto collapse val_qwk = 0, "always predict class 1" Class 4 has 1 sample → level-3 pos_weight = 403/1 = 403. Forces over-positive prediction at level 3, model compromises at "y > 0 yes, y > 1 no" everywhere.
2 Softmax head, class_weight: balanced collapse val_qwk = 0, "always predict class 4" Same 1-sample class 4 → balanced class_weight ≈ 80. Pushed predictions toward class 4 universally.
3 Softmax head, class_weight: null + label_smoothing 0.1 runs but plateaus probe QWK 0.464 (epoch 9) Trains stably but the encoder learns features that match the frozen ceiling rather than exceed it.

After attempt 3 we cached features from best.pt (epoch 9, QWK 0.464), then ran combiner / tstats / distillation sweeps. None beat the frozen ceiling.

Possible causes for LoRA-FT's weakness: rank 8 is too small to materially shift attention representations; only attn.qkv and attn.proj are LoRA-adapted (MLPs untouched); 12 epochs is short; classifier loss can't push the encoder toward rhythm if the rhythm features aren't there to begin with.

6. The smoking gun — V-JEPA features can't predict kinematic features

To isolate "appearance ≠ rhythm" from any artifact of our heads, we asked the simplest possible question: given V-JEPA cached features, can we predict the kinematic scalars at all? Procedure:

  1. Reduce the V-JEPA cache [N=404, T=192, D=1024] to a per-clip 6144-dim feature vector (mean, std, |Δ|-mean, first, last, last−first concatenated over the temporal axis).
  2. Fit Ridge regression (α=10) on the train split to predict 14 kinematic scalars (peak rate, decrement, amplitudes, FFT bands, velocity stats, etc.).
  3. Compute per-feature R² on the val split.

Negative R² across all 14 kinematic scalars. Negative R² means the V-JEPA-predicted kinematic features are worse than predicting the training-set mean. The information content of V-JEPA cached features about finger-tap rhythm is below the trivial baseline. This is the direct experimental confirmation of the appearance-vs-rhythm diagnosis: it's not a head problem, it's a feature problem.

Plugging the V-JEPA-predicted kinematic features into the same LightGBM that scores QWK 0.728 with the real kinematic features gives QWK 0.0271 — essentially random. The kinematic LightGBM is good because its inputs are good. V-JEPA cannot supply those inputs.

8. What to try next

Given the §6 diagnostic, the bottleneck is squarely in the encoder. Ranked by expected payoff per effort:

DirectionWhat it changesEffortWhy it might work
Frame-difference cache Replace RGB pixels with Δframe (or concat RGB + Δframe) as V-JEPA input. Same backbone, motion-biased input space. medium The diagnostic in §6 says the encoder needs motion-domain inputs. Frame difference makes motion the dominant signal in the input itself, forcing the encoder to encode it.
Kinematic distillation as primary objective Train the encoder (LoRA + MLP) with MSE on kinematic scalars as the only loss. Then cache features and train a CORN head. medium Aux distillation at weight 0.1–0.6 didn't help. Making it the primary loss directly forces the encoder to internalize the rhythm features that LightGBM uses.
Larger LoRA rank + include MLPs + more epochs Rank 32–64, attach LoRA to mlp.fc1/fc2 too, 30+ epochs. medium Rank 8 on attention only may be too constrained to change the representation space. Bigger LoRA gives the encoder more degrees of freedom.
JEPA SSL LoRA on may19 fold 0 train Self-supervised masked-prediction LoRA fine-tuning on may19 hand-task videos. Different gradient signal than supervised. medium Diversifies the representation away from generic V-JEPA pretraining toward this video domain. May help if combined with motion-biased inputs.
Honest 5-fold CV of frozen tstats ensemble Run the 192-cfg tstats grid on folds 1–4, get cross-fold QWK / per-class variance. low fold-0's 107 val clips is too few for stable seed ranking. Even if pure V-JEPA stays at 0.53, knowing the per-fold spread is required for an honest claim.
Stack more combiner blocks / wider d_model Pooling/head capacity. low Won't help. The features don't contain rhythm — adding head capacity learns noise.
Recommended next move: Run the §6 R²-diagnostic on a frame-difference input cache (50/50 RGB+Δframe). If R² becomes positive, motion-biased inputs are the answer; queue full pipeline. If R² remains negative, the bottleneck is deeper than input space (e.g., need full-frame optical-flow pretraining or a separate motion-aware encoder), and the kinematic baseline remains the better deployable choice for this task.
