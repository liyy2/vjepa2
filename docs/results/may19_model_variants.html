V-JEPA model variants — what we tried, visualized

Each variant is a different choice on one of the three axes the user flagged: spatial pooling, temporal handling, and feature-level fusion. Reference target: kinematic LightGBM — QWK 0.728. Best pure V-JEPA so far: QWK 0.533 (frozen tstats top-K=24 ensemble).

1. Cache variants — how a 10 s video becomes a token sequence

Every downstream head is built on top of one of these caches — a per-clip tensor extracted from V-JEPA. Each variant differs in (a) which encoder produced it, (b) the temporal stride / segments grid, and (c) how spatial patches per temporal slice are pooled.

Cache A — "fine" frozen used by every probe

192 temporal tokens × 1024-D [N=404, T=192, D=1024] spatial → squashed (user's choice). temporal → kept (192 tokens).

Default mean spatial pool. The user's preferred "squash spatial, keep temporal" arrangement.

Best downstream QWK: 0.533 (tstats top-24 ensemble) / 0.510 (combiner d=128)

Cache B — "coarse" frozen multi-scale partner

Coarser temporal grid, intended to capture across-tap rhythm at the cost of fine motion.

Best as second stream in multi-scale combiner: QWK 0.476 (slight bump over fine-only).

Cache C — "mean_std" frozen multi-pool partner

Tests whether "how varied is the activity in the frame" adds signal over just the mean.

Best multipool QWK: 0.464 (alone) / 0.453 (mean+meanstd). Did not help.

Cache D — "LoRA-FT" fine no improvement

Three LoRA-FT attempts (CORN-auto pos_weight, CORN null, softmax balanced) collapsed. The 4th, softmax unweighted, ran cleanly but produced features that matched (didn't exceed) the frozen ceiling.

Best downstream QWK on Cache D: 0.476 — actually below the frozen Cache A best.

2. Probe variants — how the cache becomes a CORN prediction

P1 — TemporalStatsMLP

The user's existing pipeline. Velocity grid: 192 configs × seeds × lrs.

Best single: 0.515
Best top-K=24 ensemble: 0.533

P2 — TemporalCornCombiner (single scale)

Cross-window combiner with order-aware 2D positional encoding. Replaces logit-mean across segments with attention.

Best (tiny d=128 L=2): 0.510
0.54M params, 6-epoch best

P3 — TemporalCornCombiner (multi-scale)

Two parallel streams (different temporal scales), each with own projection + 2D pos encoding + stream embedding, concatenated along time.

Best multi-scale: 0.476 (LoRA-FT) / 0.464 (frozen). Marginal gain.

P4 — Combiner with kinematic distillation aux head

Tests whether distilling the kinematic baseline's inputs into the V-JEPA combiner lifts QWK. Aux weight swept α ∈ {0.1, 0.3, 0.6}.

Best: 0.466 — no improvement. §6 of progress report explains why.

P5 — LightGBM on summary stats

Same recipe as the kinematic baseline (LightGBM on hand-engineered stats) but applied to V-JEPA cached features instead of MediaPipe keypoints.

0.322 — confirms the combiner architecture adds value over flat stats.

P6 — Meta's attentive probe (reference)

The original V-JEPA attentive probe. Each segment is probed independently and the logit vectors are averaged. That commutative pooling is exactly what the order-aware combiner replaces.

Best supervised LoRA-FT probe: 0.464 (the model the user disliked).

3. Multi-source combinations — fusing two streams

F1 — Multi-scale (fine + coarse)

Within the same V-JEPA encoder, different temporal grids.

Frozen: 0.464 · LoRA-FT: 0.476 (best LoRA-FT result).

F2 — Multi-pool (mean + mean+std)

Same temporal grid, different spatial pooling. Tests whether dispersion adds info.

0.453 — does not help over mean alone.

F3 — Multi-encoder (frozen + LoRA-FT)

Same temporal grid + same pool, different encoder weights — frozen ViT-L vs may19-LoRA-FT'd ViT-L.

0.453 — does not help; the two encoders' caches are highly correlated.

Diagnostic conclusion. Across all combinations of these axes — six probe variants × four cache variants × three fusion modes ≈ ~80 distinct configurations — pure V-JEPA never exceeds QWK 0.533. The §6 R² diagnostic in the progress report explains why: the cached features cannot predict the kinematic features the LightGBM baseline relies on (mean R² = −1.22). It is a feature-quality bottleneck, not an aggregation problem. The user's design instincts ("don't mean-pool logits", "keep the temporal token", "fuse multi-resolution") were correctly implemented; they didn't unlock the encoder because the rhythm signal is missing from the encoder's output to begin with.
