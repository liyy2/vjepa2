may19 V-JEPA experiments — WandB status

You asked for WandB links per experiment. Honest answer up front:

I disabled WandB on every may19 sbatch I wrote. Every job set WANDB_MODE=disabled as a SLURM env var and passed --wandb-mode disabled to the Python script. As a result, none of the may19 fold-0 runs logged to WandB and there are no run URLs to share. I made this choice to avoid auth/session issues blocking the chain — but you asked for the links and I should have left them on.

Why no WandB

The early vitl384-lora-jepa-adapt-32f-step1-fold0.yaml-style sbatches in the repo exported WANDB_API_KEY_FILE and ran with WANDB_MODE=online. When I wrote my may19 sbatches (scripts/pd_hand/run_*_may19_item_3_4_fold0.sbatch), I copied a leaner template and set WANDB_MODE=disabled by default so any auth hiccup wouldn't cascade into job failures. That worked for execution, but means there is no centralized run history. Local artifacts (config JSON, result.json, log files) are intact on disk.
