Why V-JEPA plateaus at QWK 0.55 on may19 fold 0

After ~100 configurations across four caches, six head architectures, two LoRA-FT attempts, and ensemble post-hoc — pure V-JEPA caps at QWK 0.555. The remaining gap to kinematic 0.728 is ~0.17. This isn't an optimization plateau; it's a feature-quality wall. Here's the chain of measurements that pin down why.

One-line summary. The V-JEPA encoder's output doesn't contain the finger-tap rhythm information that the kinematic baseline relies on. Adaptive coverage, multi-scale fusion, longer training, bigger heads, LoRA fine-tuning — none of those introduce new information into the encoder's output, so they all hit the same ceiling.

2. The decisive measurement: V-JEPA features cannot predict kinematic features

If V-JEPA's cached features contained the rhythm signal in any usable form, a linear projection of them could approximately reproduce the LightGBM baseline's input features. We tested that directly.

The setup

  1. For each clip, reduce V-JEPA cache [T=192, D=1024] to a 6144-dim summary vector (mean / std / |Δ|-mean / first / last / last−first over the temporal axis).
  2. Ridge regression (α=10) on train split predicting 14 kinematic scalars (peak rate, decrement, amplitudes, FFT bands, velocity stats, etc.).
  3. Report R² on val split, feature by feature.

Every single one of the 14 kinematic scalars has R² ≤ 0.04. Negative R² means V-JEPA-predicted kinematic features are worse than predicting the training-set mean. The rhythm information isn't merely hidden in some non-linear manifold of the V-JEPA cache — it isn't there. Plug those predicted features into the same LightGBM that scores 0.728 on real kinematics → it scores 0.027 (≈ random).

3. Why LoRA fine-tuning can't manufacture the missing signal

LoRA adapts attention weights (and MLP in the aggressive run). Attention combines existing token features through linear projections + softmax. It does not invent new representational axes. If individual tokens lack a "tap-amplitude-over-time" axis, attention cannot synthesize one from the appearance axes that are present.

4× more LoRA params (rank 8 → 32 + MLP) didn't lift the downstream ceiling because the limit isn't adapter capacity — it's that the supervised loss (5-way CE on 404 train clips) is too thin a gradient signal to teach an encoder a brand-new representational axis. V-JEPA's appearance-heavy pretraining bias dominates.

The train-loss / val-QWK divergence

Across every long sweep, train loss falls from ~0.7 to ~0.001 within ~30-60 epochs while val QWK plateaus around 0.50. That's the textbook signature of a representational bottleneck: the head is memorizing labels because the features it's fed don't generalize. More capacity, more epochs, more patience just lets it memorize harder.

4. Why adaptive coverage gives a small win but doesn't break the wall

The earlier "length-bin diagnostic" showed QWK falling from 0.82 (clips ≤ 8.5 s) to 0.31 (clips > 14 s) under the fixed-12-segment grid. We assumed coverage was the bottleneck. It isn't — it's a contributor, not the cause:

5. Why ensembling caps at ~0.555

Ensembling top-K configs by averaging val probabilities lifts the best single combiner (0.530) to 0.555 (top-8). The gain comes from smoothing argmax decisions on borderline clips — across seeds, the same clip's predicted class flips between adjacent labels, and the average reduces variance.

But ensembling has a hard cap: it can only smooth the noise that already lives in the predictions. It cannot create information not present in any member's features. With every member built on a V-JEPA encoder, all members share the same blind spots — the rhythm features that all of them can't see. Averaging zero with zero is still zero.

8. What's actually needed to break it

Every intervention so far operates downstream of the encoder. To break the wall the encoder's output has to change. Three viable paths:

InterventionWhy it should workEffort
Motion-explicit inputs (Δframe channel, or RGB + Δframe stacked) Motion is now the dominant signal in the encoder's input. It is forced to encode it; there's nothing else for it to attend to. Reuses V-JEPA architecture; just changes the data the encoder ingests. medium
Direct kinematic distillation as primary loss Forces the encoder + linear head to regress the 14 kinematic scalars as the only loss. Aux distillation with weight ≤ 0.6 didn't help. As primary, the encoder must learn the rhythm features by design. medium
Hybrid features at the combiner input (V-JEPA cache ‖ MediaPipe scalars) Concatenate kinematic features as a side-channel into the combiner. Trivially gets near-kinematic QWK. Useful as an upper-bound diagnostic but doesn't qualify as "pure V-JEPA". low
Recommended next push: motion-explicit inputs. Cache from Δframe input (or concatenated RGB + Δframe). If the R² diagnostic on the new cache flips from −1.22 to > 0.3, the path is open and we re-run the multi-scale adaptive sweep on it. If R² stays near zero, the V-JEPA pretrained encoder genuinely can't see rhythm and we fall back to kinematic distillation as primary objective.

9. What this plateau is not

  • Not an early-stopping issue. Patience 900, train loss → 0, val plateau confirmed.
  • Not an LR-schedule issue. Cosine to 1% of base by epoch 400 then flat; same plateau.
  • Not an aggregator issue. Cross-window combiner with 2D positional encoding replaces logit-mean. Same plateau.
  • Not a coverage issue. Adaptive K_i = ⌈duration_s⌉ gives 100% coverage on the longest clips. Same plateau.
  • Not a head-capacity issue. Tiny (0.54M) and deep (2.9M) hit the same plateau.
  • Not a class-weighting issue. Balanced, none, sqrt — all converge.
  • Not a LoRA-rank issue. Rank 8, 16, 32 give the same downstream ceiling.
  • Not a sweep-coverage issue. ~100 configs explored across seeds, sizes, depths, augmentations, schedules.

It's a property of what V-JEPA's frozen encoder outputs for a hand-tapping video. Any path forward has to change the inputs, the encoder, or the training objective for the encoder itself.
