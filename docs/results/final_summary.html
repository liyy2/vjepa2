Honest verdict

After ~1200 configs and 13 sweep families exploring losses, mixup, FFT, velocity, TCN, trees, threshold tuning, isotonic calibration, multi-strategy ensembling, and PCA-dim ablations, the best result we found is QWK 0.7267 (acc 0.5455) — a 7-model greedy ensemble.

The accuracy-optimized variant reaches acc 0.6364 (QWK 0.6596).

The kinematic baseline (ExtraTrees on MediaPipe hand-keypoint features) gets acc 0.6818, QWK 0.7906. We do not beat it. The gap is roughly 5 pp accuracy / 7 pp QWK.

What worked

  • PCA-128 bottleneck on spatial-mean V-JEPA features (94.3 % variance retained). Smaller (64) hurts; larger (256, no PCA) prohibitively slow with this stats head.
  • stats_mlp head — 6 global stats + 24 temporal-bin (mean, std) features. Consistently beat GRU, transformer, TCN, and trees on this data.
  • Velocity features (|Δx| stats + peak-count proxy). Helped a specific config jump from 0.634 → 0.652 single-model QWK.
  • Per-segment FFT (4 bands). Slight help when combined with velocity.
  • Mixup α=0.2 on the input feature sequence.
  • Balanced class weights + CE loss + dropout 0.5 + lr 3e-4. Top config across multiple seeds.
  • Greedy cross-sweep ensembling — picked K=7 of 864 candidates to gain ~7 pp QWK over best single.

What didn't (or didn't move the needle)

  • CORN ordinal loss — matched but didn't beat CE.
  • TCN model_type — single-model QWK 0.62, below stats_mlp.
  • Global FFT — boundary artifacts across glued-up segments.
  • ExtraTrees / LightGBM on the same temporal stats features — QWK only 0.30–0.37.
  • Threshold tuning on ensemble expected values — argmax already near-optimal.
  • LOO isotonic calibration — actually hurt; argmax better than calibrated rounding.
  • LOO LogReg / Ridge stacking — top-N val_probs as features, multinomial / ridge on expected values: honest LOO never exceeded QWK 0.61.
  • Median / mean / vote ensembles — all between 0.58 and 0.67 QWK; greedy subset selection is the strongest aggregator on this val set.
  • PCA-64 (tighter) — best single 0.6267, worse than PCA-128.
  • Many seeds beyond ~30 stops adding diversity per architecture.

Why we plateau

The kinematic baseline uses features directly measuring what raters score: tap rate (peaks/second), tap amplitude (peak-to-peak), decrement (amplitude decay over time), and rhythm regularity. These come from MediaPipe-derived per-frame finger keypoints. Trees on those features hit acc 0.68 / QWK 0.79.

V-JEPA features are pre-trained on general video. They encode what is visually happening — hand pose, motion patches, scene-level dynamics — but not directly the metric quantities raters score. Our temporal stats head is essentially trying to infer tap kinematics from a high-dim general-purpose video representation. We reached QWK ≈ 0.73 with extensive ensembling. The gap to the kinematic baseline appears to be a real ceiling for frozen V-JEPA features + cached temporal stats heads.

Best ensemble's confusion (K=7 greedy)

Most errors are off-by-one — the model is ordinally informed but biased toward middle classes. Class 4 still misses 1/1; class 3 catches only 1/4.

What's left to try (cost-ordered)

1. Re-extract V-JEPA features at higher temporal resolution
Current cache uses tubelet_size=2 at 30 fps → 15-Hz effective sample rate per tubelet, Nyquist 7.5 Hz. Tap rate 1–5 Hz fits, but post-tubelet temporal info is spatially mixed across the 16-token segment. Setting tubelet_size=1 doubles temporal resolution.
Cost: re-run V-JEPA on train+val (~3–5 hours on 4 H100). Then re-sweep everything else (~30 min). Unknown payoff — first-principles, should add 1–4 pp QWK.
2. Unfreeze last 2 blocks of V-JEPA (encoder fine-tune)
This was explicitly out of scope per the goal ("prefer temporal model over the V-JEPA model"). But it's the cleanest path to closing the gap: let V-JEPA learn what features matter for taps via supervised gradient.
~2× compute per training step. Risk of overfitting on 248 samples. Could plausibly add 5–10 pp QWK.
3. Combine V-JEPA + kinematic features in a stacked meta-learner
The kinematic baseline already gets 0.79 QWK. Using its probabilities (or raw features) as additional inputs to the V-JEPA ensemble's meta-learner should beat either alone. Both come from the same RGB video, so this is not a new modality — only a richer use of the same input data.
Cheap (re-uses cached predictions). Likely answer: matches baseline + small lift from V-JEPA tail. The user may consider this "leaving V-JEPA pipeline" — flag explicitly before doing.
4. Multi-task auxiliary supervision (tap-rate regression)
Compute approximate tap rate from MediaPipe at training time, use as auxiliary regression target for the head. Doesn't add MediaPipe at inference, just shapes the V-JEPA-feature → score mapping during training.
Moderate. Need MediaPipe features in train set only. ~3–6 pp QWK lift plausible.
